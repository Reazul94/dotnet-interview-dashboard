ASP.NET CORE FUNDAMENTALS & MIDDLEWARE

★★★★★ Critical Core
What is ASP.NET Core?

ASP.NET Core is a modern, cross-platform, open-source, high-performance web framework for building cloud-connected, internet-connected applications. Unlike legacy .NET Framework, it runs on Windows, Linux, and macOS, and features Kestrel web server and native Dependency Injection. ASP.NET Core হলো ওপেন সোর্স, ক্রস-প্ল্যাটফর্ম ও উচ্চ পারফরম্যান্সের ওয়েব ফ্রেমওয়ার্ক। এটি Windows, Linux ও macOS সব প্ল্যাটফর্মেই রান করে।

Q: What is middleware in ASP.NET Core?
"Middleware is software components assembled into an application pipeline to handle requests and responses. Each component can inspect, modify, or handle incoming HTTP requests and can either pass control to the next middleware in the pipeline via next() or short-circuit the pipeline."

DEPENDENCY INJECTION (DI) & SERVICE LIFETIMES

★★★★★ High Priority
Transient: Created every time requested from container.
Scoped: Created once per client HTTP request lifetime.
Singleton: Created once for application lifetime.
Q: What is a "Captive Dependency"?
"Injecting a Scoped service (like DbContext) into a Singleton creates a Captive Dependency bug, trapping the Scoped instance forever and causing thread concurrency violations and memory leaks!"

EF CORE (.AsNoTracking) & ADO.NET REVISION

★★★★★ High Priority
Q: Tracking vs AsNoTracking in EF Core?
"By default, EF Core tracks changes for all returned entities in Change Tracker. Using .AsNoTracking() on read-only queries bypasses change tracking overhead, significantly speeding up query execution and lowering memory allocation."
Q: When to use ADO.NET over EF Core?
"Use ADO.NET for high-throughput bulk data insertions, complex legacy Stored Procedures with multiple result sets, or fine-grained raw SQL performance tuning."

SQL PERFORMANCE OPTIMIZATION (12-STEP CHECKLIST)

★★★★★ Core Database
  1. 1. Reproduce query execution in non-prod with identical database volume.
  2. 2. Analyze Execution Plan (Index Scans vs Index Seeks, Key Lookups).
  3. 3. Verify Indexes on filtering/joining columns.
  4. 4. Add Covered Indexes to eliminate Key Lookups.
  5. 5. Replace SELECT * with explicit required columns.
  6. 6. Check SARGability (avoid wrapping indexed columns in functions).
  7. 7. Inspect Joins (prefer INNER JOINs where possible).
  8. 8. Avoid ORM N+1 queries using Include.
  9. 9. Update Database Statistics.
  10. 10. Fix Parameter Sniffing issues in Stored Procedures.
  11. 11. Evaluate READ COMMITTED SNAPSHOT for blocking.
  12. 12. Benchmark execution time before and after.

ENTERPRISE ARCHITECTURE & SOLID PRINCIPLES

★★★★★ High Priority
S — Single Responsibility: One reason to change.
O — Open/Closed: Open for extension, closed for modification.
L — Liskov Substitution: Derived classes substitutable for base.
I — Interface Segregation: Don't force unused methods.
D — Dependency Inversion: Depend on abstractions (interfaces).
