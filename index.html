ASP.NET CORE FUNDAMENTALS & ARCHITECTURE

★★★★★ Critical Interview Core
What is ASP.NET Core?

ASP.NET Core is a modern, cross-platform, open-source, high-performance web framework for building cloud-connected, internet-connected applications (RESTful Web APIs, Web Apps, Microservices). Unlike legacy .NET Framework, it runs on Windows, Linux, and macOS, and features a built-in lightweight web server (Kestrel) and native Dependency Injection. ASP.NET Core হলো ওপেন সোর্স, ক্রস-প্ল্যাটফর্ম ও উচ্চ পারফরম্যান্সের ওয়েব ফ্রেমওয়ার্ক। এটি Windows, Linux ও macOS সব প্ল্যাটফর্মেই রান করে।

.NET Framework vs Modern .NET (.NET 8 / 9 / 10)

.NET Framework (legacy 4.x): Windows-only, tied to IIS, heavy System.Web assembly.
Modern .NET (.NET 8/9/10): Unified, modular, cross-platform, fast, lightweight, runs natively on Linux containers. পুরাতন .NET Framework শুধুমাত্র Windows নির্ভর ছিল, পক্ষান্তরে আধুনিক .NET 8/9/10 সম্পূর্ণ ক্রস-প্ল্যাটফর্ম, দ্রুত ও কন্টেইনার-ফ্রেন্ডলি।

Kestrel Web Server

Kestrel is the default cross-platform HTTP web server in ASP.NET Core. It is asynchronous, highly optimized for I/O performance, and handles raw HTTP requests before passing them to the middleware pipeline. In enterprise production, Kestrel is usually deployed behind a reverse proxy like NGINX, Apache, or IIS for security and SSL termination. Kestrel হলো ASP.NET Core এর বিল্ট-ইন ক্রস-প্ল্যাটফর্ম ওয়েব সার্ভার। প্রোডাকশনে সাধারণত NGINX বা IIS এর পেছনে Reverse Proxy হিসেবে ব্যবহৃত হয়।

Q: What is middleware in ASP.NET Core?
"Middleware is software components assembled into an application pipeline to handle requests and responses. Each component can inspect, modify, or handle incoming HTTP requests and can either pass control to the next middleware in the pipeline via next() or short-circuit the pipeline (e.g., returning 401 Unauthorized immediately)." মিডলওয়্যার হলো রিকোয়েস্ট প্রসেসিং পাইপলাইনের উপাদান। প্রতিটি মিডলওয়্যার HTTP রিকোয়েস্ট ও রেসপন্স ইনসপেক্ট করে পরবর্তী মিডলওয়্যারে পাঠায় অথবা Short-circuit করে থামিয়ে দেয়।

DEPENDENCY INJECTION (DI) & SERVICE LIFETIMES

★★★★★ High Priority

ASP.NET Core has a built-in IoC container. Dependencies are registered in Program.cs and injected via constructor injection. ASP.NET Core এ বিল্ট-ইন IoC কন্টেইনার রয়েছে। ডিপেন্ডেন্সি Program.cs এ রেজিস্টার করা হয় এবং Constructor DI দিয়ে ইনজেক্ট করা হয়।

Lifetime Method Instance Creation Rule Common Use Case Example
builder.Services.AddTransient<IService, Service>() Transient: Created every time they are requested from the container. Lightweight, stateless utility services (e.g., calculation helper, mapper).
builder.Services.AddScoped<IService, Service>() Scoped: Created once per client HTTP request lifetime. Shared across request. DbContext, unit of work, repository classes, current user context.
builder.Services.AddSingleton<IService, Service>() Singleton: Created first time requested and lives for application lifetime. In-memory caching, app configuration settings, background queue processor.
Q: What is a "Captive Dependency" and what happens if you inject a Scoped service into a Singleton?
"Injecting a Scoped service into a Singleton creates a Captive Dependency bug. The Scoped service becomes trapped inside the Singleton's application-wide lifetime. This leads to severe issues such as DbContext thread safety violations, memory leaks, and stale data because the Scoped instance is never disposed between HTTP requests!" Singleton এর মধ্যে Scoped সার্ভিস ইনজেক্ট করলে Captive Dependency তৈরি হয়। এর ফলে DbContext কনকারেন্সি ত্রুটি, মেমরি লিক এবং পুরোনো ডেটার বাগ তৈরি হয়।

Q: What is the difference between Tracking and AsNoTracking queries in EF Core?
"By default, EF Core tracks changes for all returned entities in its Change Tracker. When SaveChangesAsync() is called, modified tracked entities generate UPDATE statements.
When executing read-only queries (e.g., retrieving lists for API GET requests), using .AsNoTracking() bypasses change tracking overhead. This significantly speeds up query execution and reduces memory allocation." ডিফল্টভাবে EF Core সব এনটিটি ট্র্যাক করে। কেবল রিড-অনলি GET কুয়েরির ক্ষেত্রে .AsNoTracking() ব্যবহার করলে Change Tracker বাইপাস হয়, যার ফলে কুয়েরি দ্রুত এক্সিকিউট হয় এবং মেমোরি বাঁচে। 
// Example Read-Only Query (Fast, Low Memory)
var activeCustomers = await _context.Customers
    .AsNoTracking()
    .Where(c => c.IsActive)
    .Include(c => c.Orders)
    .ToListAsync();

ADO.NET HIGH-PRIORITY REVISION

★★★★★ Job Spec Focus

ADO.NET is the low-level data access architecture in .NET for direct SQL execution. ADO.NET হলো .NET এর সরাসরি SQL এক্সিকিউশনের জন্য তৈরি লো-লেভেল ডাটা এক্সেস প্রযুক্তি।

ADO.NET Component Role & Responsibilities
SqlConnection Manages connection pooling and active database session stream.
SqlCommand Executes T-SQL query string or Stored Procedure against database connection.
SqlDataReader High-performance, forward-only, read-only stream of query results. Extremely fast.
SqlDataAdapter / DataSet Disconnected data architecture to populate in-memory DataTables.
ExecuteScalar() Returns the first column of the first row (ideal for COUNT or inserted Identity ID).
ExecuteNonQuery() Executes INSERT, UPDATE, DELETE and returns number of affected rows.
Q: When would you choose ADO.NET over EF Core in an enterprise project?
"EF Core provides immense developer productivity, but ADO.NET is chosen when:
1. High-throughput bulk data insertions or processing where ORM tracking overhead is unacceptable.
2. Invoking complex legacy database Stored Procedures with dynamic SQL or multiple result sets.
3. Fine-grained performance tuning where raw SQL execution plans need strict control." বাল্ক ডেটা ইনসার্ট, জটিল লিগ্যাসি Stored Procedure কল করা অথবা সরাসরি হাই-পারফরম্যান্স SQL কুয়েরি টিউনিংয়ের জন্য EF Core এর বদলে ADO.NET ব্যবহৃত হয়।

DATABASE, SQL TUNING & PRODUCTION QUERY OPTIMIZATION

★★★★★ Core Database Strength

"HOW I WOULD OPTIMIZE A SLOW PRODUCTION QUERY" (12-STEP CHECKLIST)

ধীরগতির প্রোডাকশন কুয়েরি অপ্টিমাইজ করার ১২-ধাপের চেকলিস্ট
  1. 1. Reproduce query execution in non-prod with identical database volume. নন-প্রোডাকশনে একই পরিমাণ ডেটা নিয়ে কুয়েরিটি রান করে দেখুন।
  2. 2. Analyze Execution Plan (look for Index Scans vs Index Seeks, Key Lookups, Heavy Sorting). Execution Plan চেক করুন (Index Scan নাকি Seek হচ্ছে, Key Lookup আছে কিনা দেখুন)।
  3. 3. Verify Indexes (ensure filtering/joining columns are indexed correctly). যেসব কলাম দিয়ে filtering/joining হচ্ছে সেগুলোতে সঠিক Index আছে কিনা নিশ্চিত করুন।
  4. 4. Evaluate Covered Indexes to eliminate Key Lookups. Key Lookup বন্ধ করতে Covering Index যোগ করুন।
  5. 5. Replace SELECT * with explicit required columns only. SELECT * বাদ দিয়ে প্রয়োজনীয় নির্দিষ্ট কলাম নাম দিন।
  6. 6. Check SARGability (avoid wrapping indexed columns in functions). ইনডেক্সড কলামের ওপর ফাংশন ব্যবহার করা থেকে বিরত থাকুন (SARGability)।
  7. 7. Inspect Joins (prefer INNER JOINs where possible). সম্ভব হলে INNER JOIN ব্যবহার করুন।
  8. 8. Check for N+1 Query Patterns from ORMs (ensure eager loading via Include). ORM এ N+1 প্রবলেম এড়াতে eager loading (Include) ব্যবহার করুন।
  9. 9. Update Database Statistics (outdated statistics lead to wrong query optimizer plans). ডাটাবেজ স্ট্যাটিস্টিক্স আপডেট করুন।
  10. 10. Evaluate Parameter Sniffing issues in Stored Procedures. Stored Procedure এ Parameter Sniffing আছে কিনা পরীক্ষা করুন।
  11. 11. Check Blocking/Locking Contention (evaluate READ COMMITTED SNAPSHOT). ব্লকিং ও লকিং এড়াতে READ COMMITTED SNAPSHOT বিবেচনা করুন।
  12. 12. Benchmark execution time and logical reads before and after. অপ্টিমাইজেশনের আগে ও পরে পারফরম্যান্স বেঞ্চমার্ক করুন।

ENTERPRISE ARCHITECTURE & SOLID PRINCIPLES

★★★★★ High Priority
SOLID Principles Summary
S — Single Responsibility: A class should have only one reason to change. একটি ক্লাসের শুধুমাত্র একটি দায়িত্ব থাকা উচিত।
O — Open/Closed: Software entities should be open for extension, but closed for modification. কোড এক্সটেনশনের জন্য উন্মুক্ত কিন্তু মডিফিকেশনের জন্য বন্ধ থাকা উচিত।
L — Liskov Substitution: Derived classes must be substitutable for their base classes. চাইল্ড ক্লাসগুলো বেস ক্লাসের পরিবর্তে ব্যবহারযোগ্য হতে হবে।
I — Interface Segregation: Clients shouldn't be forced to depend on methods they don't use. প্রয়োজনহীন মেথড ইন্টারফেসে রাখা উচিত নয়।
D — Dependency Inversion: Depend on abstractions, not on concrete implementations. কনক্রিট ক্লাসের ওপর নির্ভর না করে অ্যাবস্ট্রাকশনের (Interface) ওপর নির্ভর করতে হবে।
Q: Monolith vs Microservices: When would you choose Microservices?
"Microservices should NOT be the default choice due to operational complexity, distributed transactions, and network overhead. Microservices are justified when:
1. Independent Deployment & Scaling requirements across distinct domain boundaries.
2. Autonomous Engineering Teams needing clear codebase isolation.
3. Heterogeneous Technology requirements.
For most applications, a well-structured **Modular Monolith** is simpler to build, test, monitor, and deploy." অহেতুক জটিলতা বাড়াতে Microservices ব্যবহার করা উচিত নয়। স্বাধীন ডেপ্লয়মেন্ট, বড় টিম ও আলাদা টেকনোলজির প্রয়োজন হলেই কেবল Microservices নির্বাচন করা উচিত।

Q: How do you manage configuration across Dev, Staging, and Production environments in ASP.NET Core?
"ASP.NET Core uses a hierarchical configuration system that loads settings in sequence:
1. appsettings.json (Base global defaults)
2. appsettings.{Environment}.json (e.g. appsettings.Development.json)
3. Secret Manager (for local development secret storage)
4. Environment Variables / Azure Key Vault (overrides settings in production CI/CD).
