ASP.NET CORE FUNDAMENTALS & ARCHITECTURE

★★★★★ Critical Interview Core
What is ASP.NET Core?

ASP.NET Core is a modern, cross-platform, open-source, high-performance web framework for building cloud-connected, internet-connected applications (RESTful Web APIs, Web Apps, Microservices). Unlike legacy .NET Framework, it runs on Windows, Linux, and macOS, and features a built-in lightweight web server (Kestrel) and native Dependency Injection.

.NET Framework vs Modern .NET (.NET 8 / 9 / 10)

.NET Framework (legacy 4.x): Windows-only, tied to IIS, heavy System.Web assembly.
Modern .NET (.NET 8/9/10): Unified, modular, cross-platform, fast, lightweight, runs natively on Linux containers.

Kestrel Web Server

Kestrel is the default cross-platform HTTP web server in ASP.NET Core. It is asynchronous, highly optimized for I/O performance, and handles raw HTTP requests before passing them to the middleware pipeline. In enterprise production, Kestrel is usually deployed behind a reverse proxy like NGINX, Apache, or IIS for security and SSL termination.

Q: What is middleware in ASP.NET Core?
"Middleware is software components assembled into an application pipeline to handle requests and responses. Each component can inspect, modify, or handle incoming HTTP requests and can either pass control to the next middleware in the pipeline via next() or short-circuit the pipeline (e.g., returning 401 Unauthorized immediately)."

DEPENDENCY INJECTION (DI) & SERVICE LIFETIMES

★★★★★ High Priority

ASP.NET Core has a built-in IoC container. Dependencies are registered in Program.cs and injected via constructor injection.

Lifetime Method Instance Creation Rule Common Use Case Example
builder.Services.AddTransient<IService, Service>() Transient: Created every time they are requested from the container. Lightweight, stateless utility services (e.g., calculation helper, mapper).
builder.Services.AddScoped<IService, Service>() Scoped: Created once per client HTTP request lifetime. Shared across request. DbContext, unit of work, repository classes, current user context.
builder.Services.AddSingleton<IService, Service>() Singleton: Created first time requested and lives for application lifetime. In-memory caching, app configuration settings, background queue processor.
Q: What is a "Captive Dependency" and what happens if you inject a Scoped service into a Singleton?
"Injecting a Scoped service into a Singleton creates a Captive Dependency bug. The Scoped service becomes trapped inside the Singleton's application-wide lifetime. This leads to severe issues such as DbContext thread safety violations, memory leaks, and stale data because the Scoped instance is never disposed between HTTP requests!"

★★★★★ High Priority
Core Building Blocks

DbSet<TEntity>: Represents a database table set for querying and saving entities.
Migrations: Code-first incremental schema synchronization tool (dotnet ef migrations add).

Q: What is the difference between Tracking and AsNoTracking queries in EF Core?
"By default, EF Core tracks changes for all returned entities in its Change Tracker. When SaveChangesAsync() is called, modified tracked entities generate UPDATE statements.
When executing read-only queries (e.g., retrieving lists for API GET requests), using .AsNoTracking() bypasses change tracking overhead. This significantly speeds up query execution and reduces memory allocation." 
// Example Read-Only Query (Fast, Low Memory)
var activeCustomers = await _context.Customers
    .AsNoTracking()
    .Where(c => c.IsActive)
    .Include(c => c.Orders)
    .ToListAsync();

ADO.NET HIGH-PRIORITY REVISION

★★★★★ Job Spec Focus

ADO.NET is the low-level data access architecture in .NET for direct SQL execution.

ADO.NET Component Role & Responsibilities
SqlConnection Manages connection pooling and active database session stream.
SqlCommand Executes T-SQL query string or Stored Procedure against database connection.
SqlDataReader High-performance, forward-only, read-only stream of query results. Extremely fast.
SqlDataAdapter / DataSet Disconnected data architecture to populate in-memory DataTables.
ExecuteScalar() Returns the first column of the first row (ideal for COUNT or inserted Identity ID).
ExecuteNonQuery() Executes INSERT, UPDATE, DELETE and returns number of affected rows.
Q: When would you choose ADO.NET over EF Core in an enterprise project?
"EF Core provides immense developer productivity, but ADO.NET is chosen when:
1. High-throughput bulk data insertions or processing where ORM tracking overhead is unacceptable.
2. Invoking complex legacy database Stored Procedures with dynamic SQL or multiple result sets.
3. Fine-grained performance tuning where raw SQL execution plans need strict control."

DATABASE, SQL TUNING & PRODUCTION QUERY OPTIMIZATION

★★★★★ Core Database Strength

"HOW I WOULD OPTIMIZE A SLOW PRODUCTION QUERY" (12-STEP CHECKLIST)

  1. 1. Reproduce query execution in non-prod with identical database volume.
  2. 2. Analyze Execution Plan (look for Index Scans vs Index Seeks, Key Lookups, Heavy Sorting).
  3. 3. Verify Indexes (ensure filtering/joining columns are indexed correctly).
  4. 4. Evaluate Covered Indexes to eliminate Key Lookups.
  5. 5. Replace SELECT * with explicit required columns only.
  6. 6. Check SARGability (avoid wrapping indexed columns in functions like WHERE YEAR(CreatedDate) = 2026).
  7. 7. Inspect Joins (prefer INNER JOINs where possible; verify join predicates).
  8. 8. Check for N+1 Query Patterns from ORMs (ensure eager loading via Include).
  9. 9. Update Database Statistics (outdated statistics lead to wrong query optimizer plans).
  10. 10. Evaluate Parameter Sniffing issues in Stored Procedures.
  11. 11. Check Blocking/Locking Contention (evaluate READ COMMITTED SNAPSHOT).
  12. 12. Benchmark execution time and logical reads before and after.
Q: Oracle → SQL Server Transition (How to leverage your Oracle PL/SQL depth)
"In Oracle PL/SQL, I worked extensively with Packages, Triggers, Sequences, and Autonomous Transactions. In SQL Server, the concepts map directly to T-SQL Stored Procedures, Schemas, IDENTITY columns, and Transactions with Savepoints. The relational engine principles—indexes, execution plan cost analysis, locks, and ACID properties—are universal across database platforms."

ENTERPRISE ARCHITECTURE & SOLID PRINCIPLES

★★★★★ High Priority
SOLID Principles Summary
S — Single Responsibility: A class should have only one reason to change.
O — Open/Closed: Software entities should be open for extension, but closed for modification.
L — Liskov Substitution: Derived classes must be substitutable for their base classes.
I — Interface Segregation: Clients shouldn't be forced to depend on methods they don't use.
D — Dependency Inversion: Depend on abstractions, not on concrete implementations.
Q: Monolith vs Microservices: When would you choose Microservices?
"Microservices should NOT be the default choice due to operational complexity, distributed transactions, and network overhead. Microservices are justified when:
1. Independent Deployment & Scaling requirements across distinct domain boundaries.
2. Autonomous Engineering Teams needing clear codebase isolation.
3. Heterogeneous Technology requirements.
For most applications, a well-structured **Modular Monolith** is simpler to build, test, monitor, and deploy."

TESTING (xUnit / Moq) & DEVOPS CI/CD PIPELINES

AAA Testing Pattern (Arrange, Act, Assert)
[Fact]
public async Task GetCustomer_WhenExists_ReturnsOkResult()
{
    // 1. Arrange: Setup mocks and inputs
    var mockRepo = new Mock<ICustomerRepository>();
    mockRepo.Setup(r => r.GetByIdAsync(10)).ReturnsAsync(new Customer { Id = 10, Name = "KGDCL Gas" });
    var controller = new CustomerController(mockRepo.Object);

    // 2. Act: Call the method under test
    var result = await controller.GetCustomer(10);

    // 3. Assert: Verify outcome
    var okResult = Assert.IsType<OkObjectResult>(result);
    Assert.NotNull(okResult.Value);
}

ENVIRONMENT CONFIGURATION & SECRETS MANAGEMENT

★★★★★ High Priority Requirement
Q: How do you manage configuration across Dev, Staging, and Production environments in ASP.NET Core?
"ASP.NET Core uses a hierarchical configuration system that loads settings in sequence:
1. appsettings.json (Base global defaults)
2. appsettings.{Environment}.json (e.g. appsettings.Development.json)
3. Secret Manager (for local development secret storage)
4. Environment Variables / Azure Key Vault (overrides settings in production CI/CD).

Golden Rule: Never hardcode database connection strings, passwords, or JWT secret keys in repository code!"
