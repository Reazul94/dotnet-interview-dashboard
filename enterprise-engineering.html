A1. LINUX SERVER FUNDAMENTALS & ESSENTIAL COMMANDS এ১. লিনাক্স সার্ভার ফান্ডামেন্টালস এবং আবশ্যিক কমান্ডসমূহ

Command Purpose & When to Use Practical Enterprise Example
top / htop Monitor live process CPU and memory utilization. লাইভ প্রসেস CPU এবং মেমোরি ব্যবহার মনিটর করা। Identify rogue Java/ASP.NET thread spiking CPU to 100%. CPU ১০০% করা হাই-প্রসেস সনাক্ত করা।
df -h / du -sh Check disk space available and folder directory sizes. ডিস্ক স্পেস এবং ফোল্ডারের আকার পরীক্ষা করা। Diagnose full disk error caused by unrotated log files. লগ ফাইলের কারণে ডিস্ক ফুল হওয়া সমস্যা চিহ্নিত করা।
ss -tulpn / netstat Inspect listening ports and active socket connections. লিসেনিং পোর্ট এবং সকেট কানেকশন চেক করা। Verify if Kestrel (port 5000) or Tomcat (8080) is listening. পোর্ট ৫০০০ বা ৮০৮০ এ সার্ভার চালু আছে কিনা দেখা।
journalctl -u app.service -f Stream systemd service logs in real time. সিস্টেমডি সার্ভিসের লগ রিয়েল-টাইমে স্ট্রিম করা। Trace unhandled exceptions during live production deployment. প্রোডাকশন ডেপ্লয়মেন্ট এক্সেকিউশন ট্রেস করা।
Q: How do you investigate a Linux server when disk space is 100% full? প্রশ্ন: লিনাক্স সার্ভারে ডিস্ক ১০০% ফুল হলে কীভাবে ইনভেস্টিগেট করবেন?
"1. Run df -h to identify the filled filesystem partition.
2. Run du -sh /* | sort -h to locate the largest offending directory (usually /var/log or temp folders).
3. Safely truncate large unrotated application logs using > app.log instead of rm to preserve active file descriptors." "১. `df -h` দিয়ে মূল ফুল পার্টিশন খুঁজুন। ২. `du -sh /*` দিয়ে সবচেয়ে বড় ফোল্ডার বের করুন। ৩. অ্যাপের অ্যাক্টিভ ফাইল ডেসক্রিপটর বজায় রেখে `> app.log` দিয়ে বড় লগ ফাইল রিসেট করুন।"

A3. CI/CD PIPELINE FOR ASP.NET CORE / JAVA এ৩. ASP.NET Core ও Java এর জন্য CI/CD পাইপলাইন 

name: Enterprise ASP.NET Core CI/CD
on:
  push:
    branches: [ main ]
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3
    - name: Setup .NET
      uses: actions/setup-dotnet@v3
      with:
        dotnet-version: '8.0.x'
    - name: Restore dependencies
      run: dotnet restore
    - name: Build
      run: dotnet build --configuration Release --no-restore
    - name: Test
      run: dotnet test --no-restore --verbosity normal
    - name: Publish
      run: dotnet publish -c Release -o ./publish
    - name: Deploy to Linux Server via SSH
      uses: appleboy/scp-action@master
      with:
        host: ${{ secrets.SERVER_IP }}
        username: ${{ secrets.SERVER_USER }}
        key: ${{ secrets.SSH_KEY }}
        source: "./publish/*"
        target: "/var/www/myapi"
    - name: Restart systemd Service
      uses: appleboy/ssh-action@master
      with:
        host: ${{ secrets.SERVER_IP }}
        command: sudo systemctl restart myapi.service

A5. HOW TO BUILD SYSTEMS FOR HIGH CONCURRENCY এ৫. হাই কনকারেন্সি ও লাখ লাখ ইউজারের সিস্টেম স্কেলিং

★★★★★ HIGH PRIORITY ★★★★★ অতি জরুরী 
Users → Nginx Load Balancer → [API Server 1, API Server 2, API Server 3] → Redis Distributed Cache → Database (Read Replicas + Write Master)
Q: Why does this architecture scale to millions of concurrent users? প্রশ্ন: এই আর্কিটেকচার কেন লাখ লাখ ইউজারের সিস্টেমে স্কেল করে?
"1. Stateless APIs: User sessions stored in Redis allowing horizontal scaling of API nodes.
2. Redis Caching: 80%+ of read requests served in-memory (< 2ms response time), protecting DB from overload.
3. Connection Pooling: Reuses SQL connections to prevent expensive handshake bottlenecks.
4. Read Replicas: Offloads reporting and search queries away from the primary write master." "১. স্টেটলেস API: সেশন ডাটা Redis-এ থাকায় সহজে নতুন API সার্ভার যোগ করা যায়। ২. Redis ক্যাশিং: ৮০% এর বেশি পড়া সরাসরি মেমোরি থেকে করায় DB রক্ষা পায়। ৩. কানেকশন পুলিং: হ্যান্ডশেক খরচ কমায়।"
